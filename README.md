# Lyncs_Chat(普通のWebサービス版)

X風のSNSです。画面は、これまで Claude のページとして動かしていたものと同じで、裏側を「自分のサーバー + データベース」に置き換えました。

- 外部の npm 部品は **一つも使いません**(Node.js だけで動きます)。
- ログインは、**ログインID + パスワード** の独自アカウントです(Claude のアカウントは不要です)。
- 権限のチェックは、すべて **サーバー側** で行います。画面を書き換えても、他人のデータは読めません。
- 変更は、別の端末にもすぐ反映されます(サーバーからの通知で、再読み込みなしに更新)。

## 0. いちばん簡単な方法: ダブルクリックで、今すぐURLを作る(Windows)

アカウントは **1つも要りません**。友達に試してもらうのに向いています。

1. Node.js(22.5 以上)をインストールします。https://nodejs.org の「LTS」で足ります。
2. このフォルダの **`start-public.bat`** をダブルクリックします。
3. 最初に、サイト主にするログインIDを聞かれます。決めて入力し、Enter を押します。
4. 公開用の小さなプログラム(cloudflared)がないときは、自動でダウンロードするか聞かれます。Enter(はい)で進めます。
5. ブラウザが開きます。「新規登録」を選び、手順3のIDで **先に自分が登録** します。登録が終わるまで、外には公開されません。
6. 黒い画面に「みんなに配るURL」が表示されます(`https://〇〇.trycloudflare.com`)。このURLを、使ってほしい人に送ります。

**このやり方の約束ごと**
- 黒いウィンドウを閉じる、パソコンの電源を切る、スリープする、のどれかで、他の人は使えなくなります。
- 次に起動したときは、URLが変わります。
- データは、このフォルダの `data` に残ります。次に起動したときも、アカウントや投稿は消えません。
- 公開に使う Cloudflare の「Quick Tunnel」は、同社が「テストと開発のため」の機能と説明しています。稼働の保証もありません。本格的に運営するときは、下の「2」の方法に進んでください。
- ライブ更新(再読み込みなしの更新)は、この方法では使えないため、数秒ごとの自動確認に切り替わります。
- URLを知っている人は、誰でも新規登録できます。止めたいときは、運営画面の「サイト設定」で止めてください。

自分のパソコンの中だけで試すときは、**`start-local.bat`** をダブルクリックして、http://localhost:3000 を開きます。

## 1. コマンドで動かす(Windows 以外や、詳しい人向け)

Node.js 22.5 以上が必要です。

```bash
OWNER_USERNAME=koura node server/index.js
# → http://localhost:3000 を開く
# 一時的なURLで公開する場合:  node scripts/share.js
```

1. 画面で「新規登録」を選びます。ログインIDは `OWNER_USERNAME` と同じにします。このIDの人が **サイト主** になります。
2. 続けて、表示名とユーザーID(@の名前)を決めます。
3. データは `./data/lyncs.db` に保存されます。

## 2. 24時間つけっぱなしで公開する(Render + Turso)

> **はじめての人は、同じフォルダの「常時公開ガイド.md」を読んでください。** 画面ごとの手順と、今のデータの引っ越し方(`migrate-to-turso.bat`)が書いてあります。以下は、要点だけの説明です。

Render の無料プランは、ディスクが一時的なため、再起動でファイルが消えます。そのため、データは外部のデータベース(Turso)に置きます。

### 手順

1. **GitHub に置く**: このフォルダ一式を、自分のリポジトリにアップロードします(非公開で構いません)。`.env` は上げないでください(`.gitignore` 済み)。
2. **Turso でデータベースを作る**:
   - https://turso.tech でアカウントを作り、データベースを1つ作ります。
   - 接続用の **URL**(`libsql://...` の形)と **トークン** を控えます。画面の「Generate token」などで作れます。CLI を使う場合は `turso db show <名前> --url` と `turso db tokens create <名前>` です。
3. **Render でサービスを作る**:
   - https://render.com で「New +」→「Web Service」→ GitHub のリポジトリを選びます。
   - Runtime は `Node`、Build Command は空か `echo ok`、Start Command は `node --no-warnings server/index.js`、プランは `Free` にします。
   - 「Blueprint」から作ると、手順がさらに減ります。「New +」→「Blueprint」でリポジトリを選ぶと、`render.yaml` の設定が自動で入ります。入力を求められる3つ(`OWNER_USERNAME`、`TURSO_URL`、`TURSO_AUTH_TOKEN`)だけを入れてください。
   - 手で作る場合は、環境変数を入れます:
     - `NODE_VERSION` = `22`
     - `OWNER_USERNAME` = サイト主にするログインID
     - `TURSO_URL` = 手順2のURL
     - `TURSO_AUTH_TOKEN` = 手順2のトークン
   - `render.yaml` を使って作ることもできます。
4. 公開されたURL(`https://〇〇.onrender.com`)を開き、**すぐに** `OWNER_USERNAME` と同じIDで新規登録します。ほかの人に先に取られないよう、公開した直後に登録してください。
5. サイト設定(運営画面)で、サイト名、お知らせ、利用規約、承認制などを決めてから、URLを配ります。

### 無料枠について

Render と Turso の無料枠の内容(停止の条件、容量、回数)は、変更されることがあります。使う前に、それぞれの公式ページの現在の内容を確認してください。Render の無料プランでは、しばらくアクセスがないとサービスが止まり、次のアクセスの起動に時間がかかることがあります。

### 自分のサーバーで動かす(Docker)

```bash
docker build -t lyncs-chat .
docker run -d -p 3000:3000 -v lyncs-data:/data -e OWNER_USERNAME=koura lyncs-chat
```
HTTPS にするには、前段に Caddy や nginx を置いてください。そのとき `TRUST_PROXY=1` と `COOKIE_SECURE=1` を付けます。

## 3. 運営のしかた

- **運営メンバーの追加**: 運営画面の「運営メンバー」で追加します(サイト主のみ)。追加すると、その人は運営画面が使えます。以前のような「共有設定」の操作は要りません。
- **登録の制限**: 運営画面の「サイト設定」で、新規登録の停止や承認制にできます。承認制は、サーバー側でも書き込みを止めます。
- **ログイン不要にする**: 設定で「ログイン不要」にすると、ログインしていない人も読めます(書き込みは不可)。
- **パスワードを忘れた人**: メールの仕組みはないため、サイト主が再設定します。
  ```bash
  # 本番と同じ TURSO_URL / TURSO_AUTH_TOKEN を環境変数に入れたパソコンで:
  node scripts/reset-password.js <ログインID> <新しいパスワード>
  ```
  そのユーザーは、すべての端末でログアウトされます。
- **バックアップ**: `node scripts/export.js backup.json` で、ポストなどのデータを書き出します(パスワードは含まれません。画像・動画のファイルも含まれません)。定期的に保存してください。

## 4. 知っておいてほしい制限

- 予約投稿は、サーバーが動いている間だけ実行されます。無料の公開先でサイトが眠っているときは、次にアクセスがあって起きたあとに投稿されます。
- メンテナンスモード中は、予約投稿を止めます(終わったあとにまとめて投稿されます)。

- **サーバーは1台だけ** で動かしてください。2台以上に増やすと、データが食い違います。
- **規模**: 全員の分のプロフィールやポストを、各人のブラウザが読み込みます。数十人〜数百人向けです。数千人を超える場合は、データの持ち方の作り直しが必要です。
- **動画**: Turso を使うと、1ファイルの上限が既定で4MBです(`MAX_UPLOAD_MB` で変更できますが、Turso 側の上限に当たることがあります)。動画を多く使うなら、ファイル置き場を別に用意する必要があります。ローカルのディスクなら20MBまでです。
- **DMの暗号化**: 本文は暗号化して保存します。ただし、各自の鍵は、サイトのデータベース内の本人専用の場所に置いています。サーバーの管理者がデータベースを直接見られる場合、鍵に触れる可能性があります。「運営からも絶対に読めない」とは言えません。
- **メールがない**: メール認証とパスワード再設定の自動化はありません。
- **荒らし対策**: 登録は、同じIPから1時間に10回まで、ログインの失敗が続くと一時的に止まります。通報、停止、承認制もあります。公開する場合は、利用規約を設定してください。
- **個人情報**: ログインID、パスワードのハッシュ、投稿が保存されます。公開前に、扱いの方針を決めてください。

## 5. 構成

```
server/index.js   HTTPサーバー(ログイン、API、通知、画像)
server/docs.js    データの保存と権限ルール、入力の検査
server/auth.js    アカウント、パスワード(scrypt)、セッション
server/db.js      SQLite / Turso への保存
public/           画面(index.html, app.js, shim.js, auth.js)
scripts/          パスワード再設定、書き出し
test/             自動テスト(npm test。画面のテストには playwright が要ります)
```
